# Tools

| File | What it does |
|------|--------------|
| `ref.py` | **Independent** reference in pure Python (secp256k1, hash160, addresses, WIF): generates the test vectors and the keys for the end-to-end tests. `python3 tools/ref.py 0x1a838b13505b26867` |
| `ksim.c` | Abstract kangaroo simulator (points = integer exponents, no curve): used to tune zones, jumps and `dp_bits`. `gcc -O2 -o ksim tools/ksim.c -lm && ./ksim bits=32 runs=1000 K=64 dp=3 A=0.5 B=0.12 tf=0.5 jm=0.5` |
| `kang_schema2.txt` | The species of kangaroo schema 2 (`docs/en/ALGORITHMS.md` section 8.8) for `ksim`: `./ksim bits=36 runs=5000 K=4096 dp=0 design=tools/kang_schema2.txt jabs=12` (schema 1: `rck=1 tf=0.3333 jabs=12`). `rsmin=N` restarts a walker at the first distinguished point after N steps; the final line counts merges, restarts and cycle escapes per trial. Rows are `coefficient residue start end share`, with the zone in units of `W` and the modulus in the first row |
| `blsim.c` | Abstract kangaroo model with Bernstein-Lange **precomputation** (`docs/en/ALGORITHMS.md` section 8.9): a table of the `T` most frequent distinguished points, then the online search. `gcc -O2 -o blsim tools/blsim.c -lm && ./blsim bits=36 T=4096 beta=1 alpha=0.5` prints the precomputation and search steps in units of `√(W·T)` and `√(W/T)` |
| `kbands.py` | Splits the start zones of the species into bands with their own shares and optimizes them in the exact coverage model (`docs/en/ALGORITHMS.md` section 8.10); writes the layout file of schema 3. Needs numpy |
| `kang_schema3.txt` | The bands of schema 3 (format of `ksim design=`) |
| `kspec_table.py` | Turns a layout file into the species table of `src/kangaroo.c`: `python3 -I tools/kspec_table.py tools/kang_schema3.txt > src/kang_spec3.inc` |
| `kspecies.py` | Searches for species with fixed residues in the exact coverage model (section 8.8): `python3 -I tools/kspecies.py 0,1,3 12 768 0.023 40` prints the cost and the shares. Needs numpy |
| `embed.c` | Embeds the OpenCL kernels (`src/kernels/*.cl`) and the PTX modules (`src/kernels/ptx/*.ptx`) in the executable at build time |
| `gen_ptx.py` | Regenerates the CUDA modules (PTX) from the OpenCL kernels with NVRTC (`pip download nvidia-cuda-nvrtc-cu12==12.0.140`): `python3 -I tools/gen_ptx.py --nvrtc .../libnvrtc.so.12 [--ptxas .../ptxas] [--check]`. With `--ptxas` it prints registers and spills for sm_86. The NVRTC version fixes the PTX version and therefore the minimum driver (12.0 means driver 525) |
| `sass_count.py` | Counts the SASS instructions (sm_86) that NVRTC + `ptxas` produce for the CUDA-dialect kernels in `src/kernels`, and with `nvdisasm` the opcode histogram. Used for the measurements in section 8.6 (Karatsuba, row-wise product). Tools: `pip download nvidia-cuda-nvrtc-cu12==12.0.140 nvidia-cuda-nvcc-cu12==12.0.140` (NVRTC and `ptxas`), `nvdisasm` from the `cuda-nvdisasm-12-0` package of the CUDA repository. `python3 -I tools/sass_count.py --nvrtc .../libnvrtc.so.12 --ptxas .../ptxas tools/sass/kara.h tools/sass/chain.h tools/sass/variants.cl` |
| `sass/` | The forms of the 8x8-limb product measured by `sass_count.py`: `kara.h` (additive and subtractive Karatsuba), `chain.h` (row-wise, carry chain), `variants.cl` (benchmark kernels); `kara_check.c` checks on the computer that Karatsuba gives the same product as the schoolbook method |
| `bounds.py` | The calculations of section 8.7: pair coverage with integer values, the optimum of mixtures of walker species (structured 0.8165, random 1.0854), interleaved BSGS. Needs numpy |
| `ifma_emul.h` | Emulates `vpmadd52luq/huq` with AVX-512F to test the IFMA paths on CPUs without IFMA: `make BUILD=build/emu OPT="-O2 -include tools/ifma_emul.h" build/emu/pzsolve && PZ_ASSUME_IFMA=1 build/emu/pzsolve selftest`. Correctness only, not speed; `verify.sh` does this by itself |
| `gen_puzzles.py` | Verifies `data/puzzles.csv` (with `ref.py`) and `data/puzzles_withdrawn.csv` (the withdrawn puzzles 161-256) and generates `src/puzzles_data.c`; `--check` verifies that it is up to date |
| `verify.sh` | Full battery: database, tests, glibc compatibility, the CUDA path with the simulated driver, end-to-end, ASan/UBSan, TSan, Valgrind, the Windows exe under Wine (if MinGW-w64 and Wine are installed). `PZ_NVRTC=...` adds the check that the PTX modules are up to date, `PZ_SDE=/path/to/sde64` tests the IFMA engine under Intel SDE in Tiger Lake mode |
| `pty_run.py` | Runs a command in a pseudo-terminal for a few seconds and prints what it drew (used to test the multi-line panel in `verify.sh`) |
| `release.sh` | Versioned release: checks, `VERSION` bump, `verify.sh`, annotated tag; prints the push command (see `docs/en/RELEASING.md`) |
| `package_release.sh` | Builds the Linux x86-64 and Windows x86-64 packages on this machine into `dist-release/` (archives and `SHA256SUMS`), with the same checks as `verify.sh` (glibc ceiling, only system DLLs); `--pack BINARY OS ARCH` packages an existing binary (used by the release workflow on every runner). Needs MinGW-w64 and `zip`; Wine optional |
| `export_public.sh` | Exports a clean copy of the tracked tree (no binaries, archive or history) as a single initial commit, for a new public repository |
