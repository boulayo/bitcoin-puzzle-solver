# Tools

| File | What it does |
|------|--------------|
| `ref.py` | **Independent** reference in pure Python (secp256k1, hash160, addresses, WIF): generates the test vectors and the keys for the end-to-end tests. `python3 tools/ref.py 0x1a838b13505b26867` |
| `embed.c` | Embeds the OpenCL kernels (`src/kernels/*.cl`) and the PTX modules (`src/kernels/ptx/*.ptx`) in the executable at build time. With `-z` it compresses the files (an LZ77 of our own, the decoder is `src/lz.c`, a module may be compressed against another one as a dictionary, see the column `base` of `src/kernels/ptx/modules.txt`) and checks every stream with the decoder; `-T` writes the table that `tests/t_kernels.c` uses. It also holds the encoder tested by `tests/t_lz.c` |
| `ptx_table.awk` | Reads `src/kernels/ptx/modules.txt`, the one list of the CUDA modules (name, kernel, `rt_build` parameter, compression base, NVRTC options), for the `Makefile`: which files to embed, the table of `build/ptx_mods.c` that the CUDA runtime uses to pick a module, and what the simulated driver of `tests/mock_cuda` needs. A new module is one line there and its `.ptx` file |
| `gen_ptx.py` | Regenerates the CUDA modules (PTX) from the OpenCL kernels with NVRTC (`pip download nvidia-cuda-nvrtc-cu12==12.0.140`): `python3 -I tools/gen_ptx.py --nvrtc .../libnvrtc.so.12 [--ptxas .../ptxas] [--check]`. With `--ptxas` it prints registers and spills for sm_86. The NVRTC version fixes the PTX version and therefore the minimum driver (12.0 means driver 525) |
| `ifma_emul.h` | Emulates `vpmadd52luq/huq` with AVX-512F to test the IFMA paths on CPUs without IFMA: `make BUILD=build/emu OPT="-O2 -include tools/ifma_emul.h" build/emu/pzsolve && PZ_ASSUME_IFMA=1 build/emu/pzsolve selftest`. Correctness only, not speed; `verify.sh` does this by itself |
| `gen_puzzles.py` | Verifies `data/puzzles.csv` (with `ref.py`) and `data/puzzles_withdrawn.csv` (the withdrawn puzzles 161-256) and generates `src/puzzles_data.c`; `--check` verifies that it is up to date |
| `verify.sh` | Full battery: database, tests, glibc compatibility, the IFMA engine, the CUDA path with the simulated driver, end-to-end, ASan/UBSan (with `float-cast-overflow`), TSan, Valgrind, aarch64 under QEMU, the Windows exe under Wine (the last three if their tools are installed). `PZ_NVRTC=...` adds the check that the PTX modules are up to date, `PZ_SDE=/path/to/sde64` tests the IFMA engine under Intel SDE in Tiger Lake mode |
| `check_binary.sh` | `check_binary.sh linux BINARY`: no glibc symbol newer than 2.34 and no `__isoc23_*` symbol; `check_binary.sh windows BINARY`: only system DLLs. Used by both workflows, `package_release.sh` and `verify.sh`, so that the check exists once |
| `ci_apt_install.sh` | `apt-get install` for a CI runner with a time limit per try and retries (the workflows use it to install MinGW-w64 and QEMU) |
| `pty_run.py` | Runs a command in a pseudo-terminal for a few seconds and prints what it drew (used to test the multi-line panel in `verify.sh`) |
| `release.sh` | Versioned release: checks, `VERSION` bump, `verify.sh`, annotated tag; prints the push command (see `docs/en/RELEASING.md`) |
| `package_release.sh` | Builds the Linux x86-64 and Windows x86-64 packages on this machine into `dist-release/` (archives and `SHA256SUMS`), with the same checks as `verify.sh` (glibc ceiling, only system DLLs); `--pack BINARY OS ARCH` packages an existing binary (used by the release workflow on every runner). The binary in an archive is a stripped copy (no debug information; the `build/` folders keep it for gdb and Valgrind). Needs MinGW-w64 and `zip`; Wine optional |

The simulators, the layout files of the kangaroo and the scripts behind the measurements in `docs/en/RESEARCH.md` are in [`research/`](research/README.md): they are not needed to build or use the program.
