# Strumenti

| File | Cosa fa |
|------|---------|
| `ref.py` | Riferimento **indipendente** in Python puro (secp256k1, hash160, indirizzi, WIF): genera i vettori di test e le chiavi dei test end-to-end. `python3 tools/ref.py 0x1a838b13505b26867` |
| `ksim.c` | Simulatore astratto del canguro (punti = esponenti interi, nessuna curva): usato per tarare zone, salti, `dp_bits`. `gcc -O2 -o ksim tools/ksim.c -lm && ./ksim bits=32 runs=1000 K=64 dp=3 A=0.5 B=0.12 tf=0.5 jm=0.5` |
| `kang_schema2.txt` | Le specie dello schema 2 del canguro (`docs/it/ALGORITMI.md` 8.8) per `ksim`: `./ksim bits=36 runs=5000 K=4096 dp=0 design=tools/kang_schema2.txt jabs=12` (lo schema 1: `rck=1 tf=0.3333 jabs=12`). `rsmin=N` fa ripartire un camminatore al primo punto distinto dopo N passi; la riga finale conta fusioni, ripartenze e fughe dai cicli per prova. Righe `coefficiente residuo inizio fine quota`, zona in unità di `W`, modulo nella prima riga |
| `blsim.c` | Modello astratto del canguro con **precalcolo** alla Bernstein–Lange (`docs/it/ALGORITMI.md` 8.9): tabella dei `T` punti distinti più frequenti, poi ricerca online. `gcc -O2 -o blsim tools/blsim.c -lm && ./blsim bits=36 T=4096 beta=1 alpha=0.5` stampa i passi di precalcolo e di ricerca in unità di `√(W·T)` e `√(W/T)` |
| `kbands.py` | Divide le zone di partenza delle specie in fasce con quote proprie e le ottimizza nel modello esatto di copertura (`docs/it/ALGORITMI.md` 8.10); scrive il file di disposizione dello schema 3. Serve numpy |
| `kang_schema3.txt` | Le fasce dello schema 3 (formato di `ksim design=`) |
| `kspec_table.py` | Trasforma un file di disposizione nella tabella delle specie di `src/kangaroo.c`: `python3 -I tools/kspec_table.py tools/kang_schema3.txt > src/kang_spec3.inc` |
| `kspecies.py` | Cerca le specie con residui fissi nel modello esatto di copertura (8.8): `python3 -I tools/kspecies.py 0,1,3 12 768 0.023 40` stampa il costo e le quote. Serve numpy |
| `embed.c` | Incorpora i kernel OpenCL (`src/kernels/*.cl`) e i moduli PTX (`src/kernels/ptx/*.ptx`) nell'eseguibile durante la compilazione |
| `gen_ptx.py` | Rigenera i moduli CUDA (PTX) dai kernel OpenCL con NVRTC (`pip download nvidia-cuda-nvrtc-cu12==12.0.140`): `python3 -I tools/gen_ptx.py --nvrtc .../libnvrtc.so.12 [--ptxas .../ptxas] [--check]`. Con `--ptxas` stampa registri e spill per sm_86. La versione di NVRTC fissa quella del PTX e quindi il driver minimo (12.0 → driver 525) |
| `sass_count.py` | Conta le istruzioni SASS (sm_86) che NVRTC + `ptxas` producono per i kernel in dialetto CUDA di `src/kernels`, e con `nvdisasm` l'istogramma degli opcode. Usato per le misure di 8.6 (Karatsuba, prodotto per righe). Strumenti: `pip download nvidia-cuda-nvrtc-cu12==12.0.140 nvidia-cuda-nvcc-cu12==12.0.140` (NVRTC e `ptxas`), `nvdisasm` dal pacchetto `cuda-nvdisasm-12-0` del repository CUDA. `python3 -I tools/sass_count.py --nvrtc .../libnvrtc.so.12 --ptxas .../ptxas tools/sass/kara.h tools/sass/chain.h tools/sass/variants.cl` |
| `sass/` | Le forme del prodotto 8×8 limbi misurate da `sass_count.py`: `kara.h` (Karatsuba additivo e sottrattivo), `chain.h` (per righe, catena di riporti), `variants.cl` (kernel del banco di prova); `kara_check.c` controlla sul computer che Karatsuba dia lo stesso prodotto dello scolastico |
| `bounds.py` | I conti di 8.7: copertura per coppie con valori interi, ottimo delle miscele di specie di camminatori (strutturato 0,8165, casuale 1,0854), BSGS intercalato. Serve numpy |
| `ifma_emul.h` | Emula `vpmadd52luq/huq` con AVX-512F per provare i percorsi IFMA su CPU senza IFMA: `make BUILD=build/emu OPT="-O2 -include tools/ifma_emul.h" build/emu/pzsolve && PZ_ASSUME_IFMA=1 build/emu/pzsolve selftest`. Solo correttezza, non velocità; `verify.sh` lo fa da solo |
| `gen_puzzles.py` | Verifica `data/puzzles.csv` (con `ref.py`) e `data/puzzles_withdrawn.csv` (161–256) e genera `src/puzzles_data.c`; `--check` controlla che sia aggiornato |
| `verify.sh` | Batteria completa: database, test, compatibilità glibc, percorso CUDA con driver simulato, end-to-end, ASan/UBSan, TSan, Valgrind, exe Windows sotto Wine (se MinGW-w64 e Wine sono installati). `PZ_NVRTC=...` aggiunge il controllo che i PTX siano aggiornati, `PZ_SDE=/percorso/sde64` prova il motore IFMA sotto Intel SDE in modalità Tiger Lake |
| `tag_releases.sh` | Crea e pubblica i tag `vX.Y.Z` mancanti sui commit «Release vX.Y.Z» (da lanciare dal proprio computer, dove il push dei tag è possibile) |
| `pty_run.py` | Esegue un comando in un pseudo-terminale per qualche secondo e stampa ciò che ha disegnato (serve a provare il pannello a più righe in `verify.sh`) |
| `release.sh` | Rilascio versionato (vedi `docs/it/VERSIONAMENTO.md`) |
